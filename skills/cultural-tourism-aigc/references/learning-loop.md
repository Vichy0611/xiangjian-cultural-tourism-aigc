# 持续学习闭环

持续学习用于积累可复用的导演方法，不用于保存用户内容。

## 三层结构

1. **事件层**：每次完成生成后记录结构化事件，例如片型、时长、镜头数、模型路由、转场家族和角色声音数量。用户提出返修时，仅提取稳定、衔接、文字、声音、事实、叙事和表演等问题标签。
2. **候选层**：按重复次数聚合，形成待审核模式。单个项目中的偶然偏好不能直接升级为通用规则。
3. **规则层**：只有经过人工审核、能够解释适用条件并在多个项目中重复成立的模式，才写入 Skill 的正式参考文件。

## 数据边界

经验库不得保存或同步：用户姓名、项目名称、账号、密钥、文件路径、原始图片或音频、完整文案、完整提示词、完整修改意见。项目标识只能使用不可逆短哈希，并且不上传到公共仓库。

## 晋升标准

候选经验至少满足以下条件：

- 来自多个独立项目，而不是同一项目的重复重试；
- 能说明“在什么情况下有效”，而不是只报告频次；
- 不与事实核验、授权要求、用户明确选择冲突；
- 对低成本默认工作流确有帮助，或能减少返修；
- 由人审确认后再写入正式规则。

本地系统可将候选汇总写入 `references/experience-candidates.local.md`。该文件只用于本机审核，必须被版本控制忽略。可用 `python scripts/consolidate_learnings.py summary.json --output review.md` 生成便于审核的摘要。
